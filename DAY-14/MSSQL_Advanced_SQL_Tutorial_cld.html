Subqueries

A subquery (also called an inner query or nested query) is a SELECT statement embedded inside another SQL statement. Subqueries run first; their result is passed to the outer query. In T-SQL, subqueries can appear in the SELECT, FROM, WHERE, and HAVING clauses.

Key Principle: The inner query executes first. Its result is then used by the outer query — like passing the answer to one question as an input to the next question.
1.1 — Scalar Subquery (returns a single value)

A scalar subquery returns exactly one row and one column. It can be used anywhere a single value is expected — in SELECT lists, WHERE conditions, or as a calculated column.

▸ T-SQL — Scalar Subquery Examples MSSQL 
-- ── Sample tables used throughout this tutorial ──────────────────────────
--  Employees(EmployeeID, FirstName, LastName, Salary, DeptID, HireDate)
--  Departments(DeptID, DeptName, ManagerID)
--  Orders(OrderID, CustomerID, OrderDate, TotalAmount, Status)
--  Products(ProductID, ProductName, CategoryID, Price, StockQty)
--  Customers(CustomerID, FirstName, LastName, City, Email)

-- 1. Scalar subquery in WHERE — find employees earning above average
SELECT FirstName, LastName, Salary
FROM   Employees
WHERE  Salary > (
           SELECT AVG(Salary)   -- returns ONE number e.g. 62000.00
           FROM   Employees
       );

-- 2. Scalar subquery in SELECT — show each employee's salary vs. company average
SELECT
    FirstName,
    Salary,
    (SELECT AVG(Salary) FROM Employees) AS CompanyAvgSalary,
    Salary - (SELECT AVG(Salary) FROM Employees) AS DiffFromAvg
FROM Employees;

-- 3. Scalar subquery — find the most expensive product
SELECT ProductName, Price
FROM   Products
WHERE  Price = (SELECT MAX(Price) FROM Products);
1.2 — Multi-Row Subquery with IN / ANY / ALL

A multi-row subquery returns multiple rows. Use IN, NOT IN, ANY, or ALL to compare against the returned list.

▸ T-SQL — IN / NOT IN / ANY / ALL MSSQL 
-- IN: employees who work in departments located in 'London' or 'New York'
SELECT FirstName, LastName, DeptID
FROM   Employees
WHERE  DeptID IN (
           SELECT DeptID
           FROM   Departments
           WHERE  Location IN ('London', 'New York')
       );

-- NOT IN: customers who have NEVER placed an order
SELECT CustomerID, FirstName, Email
FROM   Customers
WHERE  CustomerID NOT IN (
           SELECT DISTINCT CustomerID
           FROM   Orders
           WHERE  CustomerID IS NOT NULL   -- always guard NULLs with NOT IN!
       );

-- ANY: employees earning more than ANY employee in DeptID = 3
-- (i.e. earning more than at least one person in that dept)
SELECT FirstName, Salary
FROM   Employees
WHERE  Salary > ANY (
           SELECT Salary FROM Employees WHERE DeptID = 3
       );

-- ALL: employees earning more than ALL employees in DeptID = 3
-- (i.e. earning more than the highest salary in that dept)
SELECT FirstName, Salary
FROM   Employees
WHERE  Salary > ALL (
           SELECT Salary FROM Employees WHERE DeptID = 3
       );
1.3 — Correlated Subquery

A correlated subquery references a column from the outer query. Unlike a regular subquery (runs once), a correlated subquery runs once per row of the outer query.

▸ T-SQL — Correlated Subquery (references outer query) MSSQL 
-- Find employees who earn more than the average salary of their OWN department
-- The inner query re-runs for EACH employee row using their DeptID
SELECT e.FirstName, e.LastName, e.Salary, e.DeptID
FROM   Employees e
WHERE  e.Salary > (
           SELECT AVG(e2.Salary)
           FROM   Employees e2
           WHERE  e2.DeptID = e.DeptID  -- ← references outer query alias 'e'
       );

-- Find each customer's most recent order date using correlated subquery
SELECT
    c.CustomerID,
    c.FirstName,
    (SELECT MAX(o.OrderDate)
     FROM   Orders o
     WHERE  o.CustomerID = c.CustomerID) AS LastOrderDate
FROM Customers c;
1.4 — EXISTS and NOT EXISTS

EXISTS returns TRUE if the subquery returns at least one row. It is often faster than IN for large datasets because SQL Server stops scanning as soon as it finds the first match.

▸ T-SQL — EXISTS / NOT EXISTS MSSQL 
-- EXISTS: find customers who HAVE placed at least one order
SELECT c.CustomerID, c.FirstName, c.Email
FROM   Customers c
WHERE  EXISTS (
           SELECT 1             -- SELECT 1 (or *) is idiomatic — only checking existence
           FROM   Orders o
           WHERE  o.CustomerID = c.CustomerID
       );

-- NOT EXISTS: find products that have NEVER been ordered
SELECT p.ProductID, p.ProductName, p.Price
FROM   Products p
WHERE  NOT EXISTS (
           SELECT 1
           FROM   OrderItems oi
           WHERE  oi.ProductID = p.ProductID
       );
1.5 — Derived Table (Subquery in FROM)

A derived table is a subquery used in the FROM clause — it acts like a temporary inline table. It must be given an alias.

▸ T-SQL — Derived Table (inline view) MSSQL 
-- Derived table: first calculate per-department salary stats, then filter
SELECT
    dept_stats.DeptID,
    dept_stats.AvgSalary,
    dept_stats.MaxSalary,
    dept_stats.HeadCount
FROM (
    SELECT
        DeptID,
        AVG(Salary)   AS AvgSalary,
        MAX(Salary)   AS MaxSalary,
        COUNT(*)      AS HeadCount
    FROM  Employees
    GROUP BY DeptID
) AS dept_stats         -- alias is mandatory for derived tables
WHERE dept_stats.HeadCount > 5
ORDER BY dept_stats.AvgSalary DESC;
Tip: For complex queries, prefer a CTE (WITH clause) over a derived table — it's more readable and can be referenced multiple times. CTEs are covered in the ANSI SQL reference; derived tables and CTEs are functionally equivalent in most cases.

Set Operators

Set operators combine the results of two or more SELECT statements into a single result set. The columns in each SELECT must match in number and must be compatible data types. T-SQL supports four set operators: UNION, UNION ALL, INTERSECT, and EXCEPT.

⊔ UNION / UNION ALL
UNIONAll rows, duplicates removed
UNION ALLAll rows including duplicates (faster)
∩ INTERSECT
INTERSECTOnly rows common to BOTH queries
∖ EXCEPT
EXCEPTRows in first query NOT in second
2.1 — UNION and UNION ALL
▸ T-SQL — UNION and UNION ALL with Real Examples MSSQL 
-- UNION: combine current and former employees into one list (no duplicates)
-- Column count and types must match across both SELECTs
SELECT EmployeeID, FirstName, LastName, 'Current'  AS Status
FROM   Employees
UNION
SELECT EmployeeID, FirstName, LastName, 'Former'   AS Status
FROM   FormerEmployees;
-- UNION removes duplicate rows automatically (slower — must sort/hash to detect dupes)

-- UNION ALL: same but keeps ALL rows including duplicates (usually preferred for speed)
SELECT ProductID, ProductName, Price, 'Online'   AS Source
FROM   OnlineProducts
UNION ALL
SELECT ProductID, ProductName, Price, 'InStore'  AS Source
FROM   StoreProducts;

-- UNION ALL in reporting: combine monthly order totals from different year tables
SELECT OrderMonth, TotalSales, 2023 AS Year FROM Sales2023
UNION ALL
SELECT OrderMonth, TotalSales, 2024 AS Year FROM Sales2024
ORDER BY Year, OrderMonth;   -- ORDER BY applies to the ENTIRE combined result

-- IMPORTANT: Column names come from the FIRST SELECT only
SELECT CustName AS FullName FROM Customers   -- ← column header = "FullName"
UNION ALL
SELECT EmpName              FROM Employees;   -- ← alias here is ignored
2.2 — INTERSECT (Common Rows)
▸ T-SQL — INTERSECT MSSQL 
-- INTERSECT: customers who placed orders in BOTH 2023 AND 2024
SELECT CustomerID
FROM   Orders
WHERE  YEAR(OrderDate) = 2023
INTERSECT
SELECT CustomerID
FROM   Orders
WHERE  YEAR(OrderDate) = 2024;

-- INTERSECT: employees who are also registered as customers
SELECT Email FROM Employees
INTERSECT
SELECT Email FROM Customers;
-- Only rows where the Email appears in BOTH tables are returned
2.3 — EXCEPT (Set Difference)
▸ T-SQL — EXCEPT (rows in first query NOT in second) MSSQL 
-- EXCEPT: products that exist in the catalogue but have NEVER been ordered
SELECT ProductID FROM Products
EXCEPT
SELECT ProductID FROM OrderItems;

-- EXCEPT: customers from 2023 who did NOT return in 2024 (churned customers)
SELECT CustomerID FROM Orders WHERE YEAR(OrderDate) = 2023
EXCEPT
SELECT CustomerID FROM Orders WHERE YEAR(OrderDate) = 2024;

-- Note: EXCEPT = left difference (A - B). Order matters!
-- To get B - A, simply swap the two SELECT statements.
OperatorReturnsDuplicatesTypical Use Case
UNIONRows from A + BRemovedMerge two lists, unique entries only
UNION ALLRows from A + BKept (faster)Combine partitioned tables, reports
INTERSECTRows in A AND BRemovedCommon customers across periods
EXCEPTRows in A NOT in BRemovedFind gaps, unmatched records, churn
03

Modifying Data

T-SQL provides INSERT, UPDATE, DELETE, TRUNCATE, and the powerful MERGE statement for modifying data. SQL Server also supports OUTPUT clauses to capture affected rows and TOP to limit changes.

Best Practice: Always wrap data modification in an explicit transaction (BEGIN TRAN / COMMIT / ROLLBACK) and test with a SELECT first. Use a WHERE clause to avoid unintentional full-table updates or deletes.
3.1 — INSERT
▸ T-SQL — INSERT Variations MSSQL 
-- Basic single-row INSERT
INSERT INTO Employees (FirstName, LastName, Salary, DeptID, HireDate)
VALUES ('Sarah', 'Connor', 75000.00, 2, '2024-03-01');

-- Multi-row INSERT (T-SQL allows multiple value sets)
INSERT INTO Products (ProductName, Price, StockQty, CategoryID)
VALUES
    ('Wireless Mouse',    29.99,  150, 1),
    ('USB-C Hub',         49.99,   80, 1),
    ('Laptop Stand',      39.99,  200, 2);

-- INSERT ... SELECT: copy data from another table or query
INSERT INTO ArchivedOrders (OrderID, CustomerID, OrderDate, TotalAmount)
SELECT                      OrderID, CustomerID, OrderDate, TotalAmount
FROM   Orders
WHERE  OrderDate < '2023-01-01';

-- SELECT INTO: create a NEW table and populate it in one step
SELECT CustomerID, FirstName, Email
INTO   PremiumCustomers      -- creates the table automatically
FROM   Customers
WHERE  TotalSpend > 10000;

-- OUTPUT clause: capture the auto-generated identity values after insert
INSERT INTO Employees (FirstName, LastName, Salary)
OUTPUT INSERTED.EmployeeID, INSERTED.FirstName   -- returns inserted rows
VALUES ('John', 'Doe', 60000);
3.2 — UPDATE
▸ T-SQL — UPDATE Variations MSSQL 
-- Basic UPDATE with WHERE (always use WHERE to avoid full-table update!)
UPDATE Employees
SET    Salary = Salary * 1.10,   -- 10% raise
       UpdatedAt = GETDATE()
WHERE  DeptID = 3;

-- UPDATE with subquery in SET — set salary to department average
UPDATE Employees
SET    Salary = (
           SELECT AVG(Salary)
           FROM   Employees
           WHERE  DeptID = 5
       )
WHERE  EmployeeID = 42;

-- UPDATE with JOIN (T-SQL specific — update table using data from another table)
UPDATE e
SET    e.DeptName = d.DeptName
FROM   Employees e
JOIN   Departments d ON e.DeptID = d.DeptID
WHERE  d.Location = 'London';

-- TOP: update only the first N rows (useful for batch processing)
UPDATE TOP(100) Orders
SET    Status = 'Processed'
WHERE  Status = 'Pending';

-- OUTPUT: capture old and new values during an update (great for auditing)
UPDATE Products
SET    Price = Price * 1.05
OUTPUT
    DELETED.ProductID,
    DELETED.Price  AS OldPrice,
    INSERTED.Price AS NewPrice
WHERE  CategoryID = 1;
3.3 — DELETE and TRUNCATE
▸ T-SQL — DELETE vs TRUNCATE MSSQL 
-- DELETE with WHERE — removes specific rows
DELETE FROM Orders
WHERE  OrderDate < '2020-01-01'
  AND  Status = 'Cancelled';

-- DELETE with JOIN (T-SQL specific)
DELETE oi
FROM   OrderItems oi
JOIN   Orders     o  ON oi.OrderID = o.OrderID
WHERE  o.Status   = 'Cancelled';

-- DELETE with subquery
DELETE FROM Products
WHERE  ProductID NOT IN (
           SELECT DISTINCT ProductID
           FROM   OrderItems
       );   -- delete products that have never been ordered

-- OUTPUT with DELETE — capture what you deleted (for audit logging)
DELETE FROM TempLogs
OUTPUT DELETED.LogID, DELETED.Message, DELETED.CreatedAt
WHERE  CreatedAt < DATEADD(DAY, -30, GETDATE());

-- TRUNCATE TABLE — removes ALL rows; faster than DELETE (no row-level logging)
-- Cannot use WHERE. Cannot be rolled back easily. Resets IDENTITY counter.
TRUNCATE TABLE StagingImport;   -- fast, non-logged, resets identity
DELETE vs TRUNCATE: DELETE logs each row removal, fires DELETE triggers, can use WHERE, and can be rolled back. TRUNCATE is minimally logged, is much faster on large tables, resets the identity counter, but cannot be filtered and does not fire DML triggers.
3.4 — MERGE (Upsert)

MERGE performs INSERT, UPDATE, or DELETE in a single statement based on whether rows match between a source and target table.

▸ T-SQL — MERGE (Upsert Pattern) MSSQL 
-- MERGE: sync Products table from a staging/import table
MERGE Products AS target
USING StagingProducts AS source
    ON (target.ProductID = source.ProductID)

WHEN MATCHED AND target.Price <> source.Price THEN
    -- Row exists in both — update price if changed
    UPDATE SET
        target.Price     = source.Price,
        target.StockQty  = source.StockQty,
        target.UpdatedAt = GETDATE()

WHEN NOT MATCHED BY TARGET THEN
    -- New product in source — insert it
    INSERT (ProductID, ProductName, Price, StockQty)
    VALUES (source.ProductID, source.ProductName, source.Price, source.StockQty)

WHEN NOT MATCHED BY SOURCE THEN
    -- Product in target but not in source — delete it (discontinued)
    DELETE

OUTPUT
    $action AS ActionTaken,   -- 'INSERT', 'UPDATE', or 'DELETE'
    COALESCE(INSERTED.ProductID, DELETED.ProductID) AS ProductID;

Writing Expressions — Calculations

SQL expressions for calculations include arithmetic operators, math functions, aggregate functions, and window functions. In T-SQL, expressions appear in SELECT lists, WHERE filters, ORDER BY, and computed column definitions.

4.1 — Arithmetic Operators and Math Functions
▸ T-SQL — Arithmetic and Math Functions MSSQL 
-- Basic arithmetic operators: + - * / % (modulo)
SELECT
    OrderID,
    Quantity,
    UnitPrice,
    Quantity * UnitPrice                              AS LineTotal,
    Quantity * UnitPrice * (1 - DiscountPct)          AS DiscountedTotal,
    Quantity * UnitPrice * (1 + 0.20)                 AS TotalWithVAT,
    OrderID % 2                                         AS IsEvenOrder  -- modulo
FROM OrderItems;

-- Common T-SQL Math Functions
SELECT
    ROUND(17.567, 2)          AS Rounded,          -- 17.57
    FLOOR(17.9)               AS FloorVal,         -- 17 (round down)
    CEILING(17.1)             AS CeilVal,          -- 18 (round up)
    ABS(-250.00)              AS AbsVal,           -- 250.00
    SQRT(144)                 AS SqrtVal,          -- 12.0
    POWER(2, 10)              AS PowerVal,         -- 1024
    LOG(100)                  AS LogVal,           -- natural log
    LOG10(1000)               AS Log10Val,         -- 3.0
    PI()                      AS PiVal,             -- 3.14159...
    RAND()                    AS RandomFloat;       -- random 0-1

-- Integer division vs. decimal division
SELECT
    10 / 3                     AS IntDiv,            -- 3 (integer!)
    10 / 3.0                   AS DecDiv,            -- 3.333... (one decimal literal forces float)
    CAST(10 AS DECIMAL(10,2)) / 3 AS CastDiv;          -- 3.33

-- Real-world: calculate profit margin percentage per product
SELECT
    ProductName,
    SalePrice,
    CostPrice,
    (SalePrice - CostPrice) / NULLIF(SalePrice, 0) * 100  AS MarginPct
    -- NULLIF prevents division-by-zero error when SalePrice = 0
FROM Products;
4.2 — Aggregate Functions in Expressions
▸ T-SQL — Aggregate Calculation Expressions MSSQL 
-- Aggregate functions with expressions
SELECT
    DeptID,
    COUNT(*)                          AS TotalEmployees,
    COUNT(DISTINCT JobTitle)          AS UniqueJobTitles,
    SUM(Salary)                       AS TotalPayroll,
    AVG(Salary)                       AS AvgSalary,
    MIN(Salary)                       AS MinSalary,
    MAX(Salary)                       AS MaxSalary,
    MAX(Salary) - MIN(Salary)        AS SalaryRange,     -- expression on aggregates
    SUM(Salary) / COUNT(*) * 12     AS AnnualPayroll    -- combined expression
FROM   Employees
GROUP BY DeptID
HAVING   COUNT(*) > 3;              -- filter on aggregate result

-- Date calculations — difference between dates, adding intervals
SELECT
    EmployeeID,
    HireDate,
    DATEDIFF(YEAR,  HireDate, GETDATE())   AS YearsOfService,
    DATEDIFF(MONTH, HireDate, GETDATE())   AS MonthsOfService,
    DATEADD(YEAR, 1, HireDate)             AS OneYearAnniversary,
    DATEADD(DAY, 90, GETDATE())            AS ProrationEndDate
FROM Employees;

Writing Expressions — String Manipulation

T-SQL provides a rich library of string functions for building, parsing, cleaning, and formatting text data. These are commonly used in data cleaning, reporting, and ETL pipelines.

5.1 — Core String Functions
▸ T-SQL — Essential String Functions with Examples MSSQL 
-- ── LENGTH & CASE ────────────────────────────────────────────────
SELECT
    LEN('Hello World')           AS Len,           -- 11 (excludes trailing spaces)
    DATALENGTH('Hello')          AS ByteLen,       -- bytes (5 for VARCHAR, 10 for NVARCHAR)
    UPPER('hello world')         AS UpperCase,     -- 'HELLO WORLD'
    LOWER('HELLO WORLD')         AS LowerCase,     -- 'hello world'

-- ── TRIMMING & PADDING ───────────────────────────────────────────
    LTRIM('   hello')             AS LTrimmed,      -- 'hello'
    RTRIM('hello   ')             AS RTrimmed,      -- 'hello'
    TRIM('  hello  ')             AS BothTrimmed,   -- 'hello' (SQL Server 2017+)
    LEFT('Hello World', 5)       AS LeftChars,     -- 'Hello'
    RIGHT('Hello World', 5)      AS RightChars,    -- 'World'

-- ── SUBSTRING, CHARINDEX, PATINDEX ──────────────────────────────
    SUBSTRING('Hello World', 7, 5) AS Mid,          -- 'World' (start,length)
    CHARINDEX('World', 'Hello World') AS Position,  -- 7 (1-based position)
    PATINDEX('%[0-9]%', 'abc123') AS FirstDigit,  -- 4 (position of first digit)

-- ── REPLACE & STUFF ──────────────────────────────────────────────
    REPLACE('Hi World', 'World', 'SQL') AS Replaced,-- 'Hi SQL'
    STUFF('Hello!', 6, 1, ' World')  AS Stuffed,   -- 'Hello World' (pos,del_len,insert)

-- ── CONCATENATION ────────────────────────────────────────────────
    'Hello' + ' ' + 'World'      AS Concat,       -- 'Hello World' (+)
    CONCAT('Hello', ' ', 'World')AS ConcatFn,     -- safer (ignores NULLs)
    CONCAT_WS(',', 'A', 'B', 'C')AS ConcatSep;    -- 'A,B,C' (with separator)
5.2 — Practical String Manipulation Scenarios
▸ T-SQL — Real-World String Expressions MSSQL 
-- Build a formatted full name from parts
SELECT
    CONCAT(UPPER(LEFT(FirstName, 1)), LOWER(SUBSTRING(FirstName, 2, 100)),
           ' ',
           UPPER(LEFT(LastName, 1)),  LOWER(SUBSTRING(LastName,  2, 100)))
    AS FormattedName    -- "Sarah Connor" — proper case
FROM Employees;

-- Extract domain from email address
SELECT
    Email,
    SUBSTRING(Email,
              CHARINDEX('@', Email) + 1,
              LEN(Email))   AS EmailDomain
FROM Customers;   -- e.g. 'john@gmail.com' → 'gmail.com'

-- Mask sensitive data — show only last 4 digits of card number
SELECT
    REPLICATE('*', LEN(CardNumber) - 4) + RIGHT(CardNumber, 4)
    AS MaskedCard   -- e.g. '************1234'
FROM PaymentMethods;

-- FORMAT function — locale-aware number and date formatting
SELECT
    FORMAT(1234567.89, 'N2')           AS FormattedNum,    -- '1,234,567.89'
    FORMAT(1234567.89, 'C2', 'en-US')  AS Currency,       -- '$1,234,567.89'
    FORMAT(GETDATE(), 'dd-MMM-yyyy')   AS FormattedDate,  -- '04-Mar-2026'
    FORMAT(GETDATE(), 'HH:mm:ss')      AS TimeOnly;        -- '14:30:00'

-- Data cleaning: remove extra spaces, standardize format
UPDATE Customers
SET
    FirstName = TRIM(REPLACE(FirstName, '  ', ' ')),   -- collapse double spaces
    Email     = LOWER(TRIM(Email)),                    -- normalize to lowercase
    Phone     = REPLACE(REPLACE(REPLACE(Phone,' ',''),'-',''),'(','')
WHERE CustomerID > 0;

-- STRING_AGG: aggregate multiple rows into a comma-separated string (SQL Server 2017+)
SELECT
    DeptID,
    STRING_AGG(FirstName, ', ') WITHIN GROUP (ORDER BY FirstName)
    AS EmployeeList   -- 'Alice, Bob, Carol, David'
FROM Employees
GROUP BY DeptID;

Writing Expressions — Conditional Logic

T-SQL provides several ways to write conditional logic directly inside a query: the CASE expression, IIF(), CHOOSE(), COALESCE(), NULLIF(), and ISNULL(). These allow branching without procedural code.

6.1 — CASE Expression

The CASE expression is the most powerful and versatile conditional tool in SQL. It comes in two forms: Simple CASE (compares one value) and Searched CASE (evaluates Boolean conditions).

▸ T-SQL — Simple CASE and Searched CASE MSSQL 
-- ── SIMPLE CASE: compare one expression against fixed values ─────
SELECT
    OrderID,
    Status,
    CASE Status                          -- evaluate Status once
        WHEN 'P'  THEN 'Pending'
        WHEN 'S'  THEN 'Shipped'
        WHEN 'D'  THEN 'Delivered'
        WHEN 'C'  THEN 'Cancelled'
        ELSE           'Unknown'
    END AS StatusDescription
FROM Orders;

-- ── SEARCHED CASE: evaluate different Boolean conditions ──────────
SELECT
    EmployeeID,
    Salary,
    CASE
        WHEN Salary <  40000  THEN 'Grade 1 — Entry Level'
        WHEN Salary <  70000  THEN 'Grade 2 — Mid Level'
        WHEN Salary < 100000  THEN 'Grade 3 — Senior Level'
        ELSE                        'Grade 4 — Executive'
    END AS SalaryGrade
FROM Employees;

-- ── CASE in ORDER BY — custom sort order ─────────────────────────
SELECT OrderID, Status, OrderDate
FROM   Orders
ORDER BY
    CASE Status
        WHEN 'Urgent'    THEN 1
        WHEN 'Pending'   THEN 2
        WHEN 'Shipped'   THEN 3
        ELSE                  99
    END;   -- Urgent orders appear at the top

-- ── CASE in GROUP BY / aggregation ───────────────────────────────
SELECT
    CASE
        WHEN Salary <  50000 THEN 'Low'
        WHEN Salary <  90000 THEN 'Medium'
        ELSE                       'High'
    END           AS SalaryBand,
    COUNT(*)      AS EmployeeCount,
    AVG(Salary)   AS AvgInBand
FROM    Employees
GROUP BY
    CASE                          -- GROUP BY must repeat the same CASE
        WHEN Salary <  50000 THEN 'Low'
        WHEN Salary <  90000 THEN 'Medium'
        ELSE                       'High'
    END;
6.2 — IIF, CHOOSE, COALESCE, NULLIF, ISNULL
▸ T-SQL — Shorthand Conditional Functions MSSQL 
-- IIF: inline IF (T-SQL specific — shorthand for a 2-branch CASE)
-- IIF(condition, true_value, false_value)
SELECT
    OrderID,
    TotalAmount,
    IIF(TotalAmount >= 1000, 'High Value', 'Standard') AS OrderTier,
    IIF(StockQty < 10,        'Reorder Now', 'OK')        AS StockAlert
FROM Orders;

-- CHOOSE: return a value at a 1-based index position from a list
SELECT
    CHOOSE(MONTH(GETDATE()), 'Q1','Q1','Q1','Q2','Q2','Q2',
                               'Q3','Q3','Q3','Q4','Q4','Q4')
    AS CurrentQuarter,

    CHOOSE(DATEPART(WEEKDAY, GETDATE()),
           'Sunday','Monday','Tuesday','Wednesday',
           'Thursday','Friday','Saturday')
    AS DayName;

-- COALESCE: return the first non-NULL value from a list
-- Standard SQL — preferred over ISNULL for portability
SELECT
    CustomerID,
    COALESCE(Phone, Mobile, WorkPhone, 'No contact number')
    AS BestPhone   -- returns the first non-NULL phone number
FROM Customers;

-- ISNULL: T-SQL specific — replaces NULL with a specified value (2 args only)
SELECT
    ProductName,
    ISNULL(Discount, 0)    AS EffectiveDiscount,   -- treat NULL as 0
    ISNULL(Description, 'No description available')
                            AS Description
FROM Products;

-- NULLIF: returns NULL if both arguments are EQUAL; otherwise returns the first
-- Use to prevent division-by-zero errors
SELECT
    ProductName,
    Revenue,
    Units,
    Revenue / NULLIF(Units, 0)  AS RevenuePerUnit
    -- When Units = 0: NULLIF returns NULL → division produces NULL (not an error)
    -- When Units ≠ 0: NULLIF returns Units → normal division proceeds
FROM SalesData;
6.3 — Combining Conditional Logic — Complete Real-World Example
▸ T-SQL — Combined Expressions: Calculations + Strings + Conditionals MSSQL 
-- A comprehensive ORDER SUMMARY report combining all expression types
SELECT
    -- String manipulation: formatted customer name
    CONCAT(c.FirstName, ' ', UPPER(c.LastName))    AS Customer,

    -- Calculation: line total with discount
    ROUND(oi.Quantity * oi.UnitPrice
          * (1 - COALESCE(oi.DiscountPct, 0)), 2)  AS LineTotal,

    -- Conditional: delivery priority based on order value
    CASE
        WHEN o.TotalAmount >= 500  THEN '⭐ Express — Free'
        WHEN o.TotalAmount >= 100  THEN 'Standard — Free'
        ELSE                              'Standard — £3.99'
    END                                               AS DeliveryOption,

    -- IIF: flag overdue orders
    IIF(o.Status <> 'Delivered'
        AND o.ExpectedDate < GETDATE(), 'OVERDUE', 'On Track')
                                                      AS DeliveryStatus,

    -- Date calculation: days until expected delivery
    DATEDIFF(DAY, GETDATE(), o.ExpectedDate)       AS DaysToDelivery,

    -- String: masked order reference
    'ORD-' + RIGHT('0000' + CAST(o.OrderID AS VARCHAR), 6)
                                                      AS OrderRef,

    -- Conditional aggregate: count items and flag large orders
    COUNT(oi.ProductID) OVER (PARTITION BY o.OrderID)  AS ItemCount

FROM   Orders o
JOIN   Customers  c  ON o.CustomerID  = c.CustomerID
JOIN   OrderItems oi ON o.OrderID     = oi.OrderID
WHERE  o.OrderDate >= DATEADD(MONTH, -3, GETDATE())
ORDER BY
    IIF(o.Status <> 'Delivered' AND o.ExpectedDate < GETDATE(), 0, 1),
    o.TotalAmount DESC;   -- overdue orders first, then by value
