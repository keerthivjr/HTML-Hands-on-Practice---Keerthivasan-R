01 — Foundation

Coding Standards

Consistent standards reduce cognitive load during reviews, onboarding, and maintenance. C# 12 introduces features that allow more expressive, concise, and safe code.

🏗

Primary Constructors (C# 12)

Primary constructors let you declare constructor parameters directly on the class declaration. Use them for simple dependency injection and record-like classes to reduce boilerplate.

Before — C# 11 VERBOSE 
public class OrderService
{
    private readonly IOrderRepository _repo;
    private readonly ILogger<OrderService> _logger;

    public OrderService(
        IOrderRepository repo,
        ILogger<OrderService> logger)
    {
        _repo   = repo;
        _logger = logger;
    }
}
After — C# 12 Primary Constructor CLEAN 
public class OrderService(
    IOrderRepository repo,
    ILogger<OrderService> logger)
{
    public async Task<Order> GetAsync(Guid id)
    {
        logger.LogInformation("Fetching {Id}", id);
        return await repo.FindAsync(id);
    }
}
⚠ Primary constructor parameters are captured by the class — avoid mutating them. If mutation is needed, assign them to a private field explicitly.
📦

Collection Expressions (C# 12)

A unified, concise syntax for creating arrays, lists, spans, and other collections using bracket notation. The compiler selects the most efficient representation.

Before OLD STYLE 
int[] nums = new int[] { 1, 2, 3 };
List<string> tags = new List<string>
    { "dotnet", "csharp" };

var combined = nums
    .Concat(new[] { 4, 5 })
    .ToArray();
After — Collection Expressions C# 12 
int[] nums = [1, 2, 3];
List<string> tags = ["dotnet", "csharp"];

// Spread operator (..) to merge
int[] extra = [4, 5];
int[] combined = [..nums, ..extra];

// Works with Span<T> — zero allocation!
Span<int> span = [10, 20, 30];
⚡

Inline Arrays (C# 12)

Inline arrays are a new struct feature enabling fixed-size, stack-allocated buffers without unsafe code. Used internally by the runtime and available to library authors for high-performance scenarios.

Inline Array — Fixed-size Stack Buffer C# 12 / HIGH PERF 
[System.Runtime.CompilerServices.InlineArray(8)]
public struct Buffer8<T>
{
    private T _element0; // runtime repeats this N times
}

// Usage — zero heap allocation
Buffer8<int> buf = default;
buf[0] = 42;
buf[1] = 99;

foreach (var val in buf)
    Console.WriteLine(val);
λ

Default Lambda Parameters (C# 12)

Lambdas can now have default parameter values, just like regular methods. Reduces the need for overloads in callback-heavy APIs.

Default Lambda Parameters C# 12 
// Lambda with defaults
var greet = (string name, string prefix = "Hello")
    => $"{prefix}, {name}!";

Console.WriteLine(greet("Alice"));           // Hello, Alice!
Console.WriteLine(greet("Bob", "Hey"));     // Hey, Bob!

// Practical: configurable retry delegate
Func<int, TimeSpan> backoff =
    (int attempt, int baseMs = 100)
        => TimeSpan.FromMilliseconds(baseMs * (1 << attempt));

var delay = backoff(3);  // 800ms
02 — Conventions

Naming Conventions

Consistent naming is the single highest-ROI standard. It makes code self-documenting and eliminates whole categories of questions during review.

Types & Namespaces
PascalCase for all types, interfaces, enums, namespaces.
OrderService, IPaymentGateway, MyApp.Orders
Methods & Properties
PascalCase for methods, properties, events.
GetOrderAsync(), TotalAmount, OnCompleted
Local Variables & Parameters
camelCase. Avoid single letters except in short lambdas.
orderId, maxRetries, x => x.Id
Private Fields
Prefix with underscore + camelCase.
_repository, _logger, _cacheExpiry
Constants & Static Readonly
PascalCase for both.
MaxPageSize, DefaultTimeout
Interfaces
Prefix with I (PascalCase after).
IOrderRepository, IAsyncDisposable
Generic Type Parameters
Single T for simple, descriptive T-prefix for complex.
T, TKey, TValue, TResult
Async Methods
Always suffix with Async.
GetOrderAsync(), SaveChangesAsync()

Naming in Practice

Avoid BAD 
public class mgr  // abbreviation
{
    int x;           // meaningless
    string Data;     // field, not property

    public List<Order> Get() // missing Async
        => ...;

    public void DoIt() // vague intent
        => ...;
}
Prefer GOOD 
public class OrderManager
{
    private int _retryCount;
    public string Data { get; init; }

    public async Task<List<Order>> GetActiveAsync()
        => ...;

    public async Task ProcessPendingOrdersAsync()
        => ...;
}
03 — Safety

Nullability & Pattern Matching

Enable nullable reference types globally. Combine with C# pattern matching to write null-safe, expressive code without defensive null-checks cluttering logic.

🛡

Nullable Reference Types

Enable #nullable enable project-wide. Distinguish nullable from non-nullable at the type level.

Nullable Reference Types + Null-Coalescing RECOMMENDED 
// .csproj — enable globally
// <Nullable>enable</Nullable>

public record Customer(
    string Name,            // non-nullable — must be set
    string? MiddleName,     // nullable — optional
    Address? ShippingAddress
);

public string GetDisplayName(Customer customer)
{
    // Null-conditional + null-coalescing
    var middle = customer.MiddleName is not null
        ? $" {customer.MiddleName[0]}."
        : string.Empty;

    return $"{customer.Name}{middle}";
}

// Null-forgiving when you're certain (use sparingly)
var city = customer.ShippingAddress!.City;
🔍

Pattern Matching

C# 8–12 progressively expanded pattern matching. Use switch expressions, list patterns, and property patterns instead of nested if-else chains.

Old — Nested if/else AVOID 
string Classify(Order o)
{
    if (o == null)
        return "invalid";
    if (o.Total > 1000 && o.IsPriority)
        return "vip";
    if (o.Total > 1000)
        return "high-value";
    return "standard";
}
Modern — Switch Expression + Patterns PREFERRED 
string Classify(Order? o) => o switch
{
    null                           => "invalid",
    { Total: > 1000, IsPriority: true }
                                   => "vip",
    { Total: > 1000 }             => "high-value",
    _                              => "standard"
};
List Patterns (C# 11) — Deconstruct sequences C# 11+ 
string DescribeList(int[] nums) => nums switch
{
    []              => "empty",
    [var single]    => $"one item: {single}",
    [var a, var b] => $"two items: {a}, {b}",
    [.., 42]       => "ends with 42",
    [1, ..]         => "starts with 1",
    _               => "many items"
};
04 — Type Design

Records, Structs & Type Hierarchy

Choose the right type for your data. Records are immutable value-semantic types ideal for DTOs, domain events, and query results.

📋

Record Types — When & How

Records provide value equality, with-expressions, and deconstruction out of the box. Prefer them over classes for immutable data carriers.

Records — DTOs, Domain Events, Value Objects IDIOMATIC 
// Positional record — compact syntax
public record OrderCreatedEvent(
    Guid     OrderId,
    Guid     CustomerId,
    decimal  Total,
    DateTime CreatedAt);

// With-expression: non-destructive update
var original = new OrderCreatedEvent(
    Guid.NewGuid(), Guid.NewGuid(),
    299.99m, DateTime.UtcNow);

var corrected = original with { Total = 349.99m };

// Value equality — no custom Equals needed
var copy = original with { };
Console.WriteLine(original == copy); // True

// Deconstruction
var (orderId, custId, total, _) = original;

// record struct — stack-allocated value equality
public readonly record struct Money(
    decimal Amount, string Currency);

var usd = new Money(100m, "USD");
var eur = usd with { Currency = "EUR", Amount = 92m };
ℹ Use record (class) for reference semantics with value equality. Use readonly record struct for small, frequently-allocated value objects that benefit from stack allocation.
🔒

Required Members & Init-Only

required keyword (C# 11) forces callers to set properties during object initialization. Combine with init to create immutable objects with flexible construction.

required + init — Safe Object Construction C# 11/12 
public class CreateOrderCommand
{
    public required Guid   CustomerId  { get; init; }
    public required string ProductSku  { get; init; }
    public required int    Quantity    { get; init; }
    public          string Note       { get; init; } = "";
}

// ✓ Compiles — all required properties set
var cmd = new CreateOrderCommand
{
    CustomerId = Guid.NewGuid(),
    ProductSku = "SKU-001",
    Quantity   = 2
};

// ✗ Compile error — missing required members
// var bad = new CreateOrderCommand { Quantity = 1 };
05 — Performance

Performance Best Practices

.NET 8 ships with significant runtime optimisations — DATAS garbage collector, tiered JIT, frozen objects. Write code that cooperates with these improvements.

❄

Frozen Collections (.NET 8)

FrozenDictionary and FrozenSet are read-only collections optimised for fast lookup. Ideal for static configuration data, lookup tables, and feature flags loaded at startup.

Dictionary (mutable) BASELINE 
// Mutable — lock needed for thread safety
private static readonly
    Dictionary<string, int> _codes
        = new()
{
    { "USD", 840 },
    { "EUR", 978 },
    { "GBP", 826 }
};
FrozenDictionary (.NET 8) FASTER LOOKUP 
using System.Collections.Frozen;

private static readonly
    FrozenDictionary<string, int> _codes =
        new Dictionary<string, int>
        {
            { "USD", 840 },
            { "EUR", 978 }
        }.ToFrozenDictionary();

// Thread-safe, no lock needed, ~2× faster reads
if (_codes.TryGetValue("USD", out var code))
    ...
🔤

String Handling — Avoid Allocations

Strings are the #1 source of unnecessary heap allocations. Use Span<char>, SearchValues, and CompositeFormat to minimise pressure on the GC.

SearchValues + Span — Zero-Allocation String Scanning (.NET 8) HIGH PERF 
using System.Buffers;

// Pre-build the search set once — O(1) lookup
private static readonly SearchValues<char> _special =
    SearchValues.Create("!@#$%^&*()");

public static bool HasSpecialChar(ReadOnlySpan<char> input)
    => input.ContainsAny(_special); // no allocation!

// CompositeFormat — parse format string once
private static readonly CompositeFormat _fmt =
    CompositeFormat.Parse("Order {0} placed by {1}");

public string FormatMessage(Guid orderId, string name)
    => string.Format(
        System.Globalization.CultureInfo.InvariantCulture,
        _fmt, orderId, name);
⚡

LINQ — Right Tool, Right Place

LINQ is expressive but can hide allocations. Use Count() vs .Count, short-circuit with Any(), and prefer Where+Select over nested LINQ to keep allocations minimal.

Common LINQ Pitfalls AVOID 
// Multiple enumerations
if (orders.Count() > 0)     // use Any()
    ...

// Materialises entire list to check one
var found = orders
    .Where(o => o.Id == id)
    .ToList()              // unnecessary
    .FirstOrDefault();

// Select inside Where causes double iteration
orders.Select(o => o.Total)
      .Where(t => t > 100);
Optimised LINQ PREFER 
// Short-circuit, no full enumeration
if (orders.Any())  ...

// No intermediate list
var found = orders
    .FirstOrDefault(o => o.Id == id);

// Filter then project (less work per item)
orders.Where(o => o.Total > 100)
      .Select(o => o.Total);

// For hot paths — avoid LINQ entirely
foreach (var o in orders)
    if (o.Total > 100) Process(o);
♻

Object Pooling

Reuse expensive objects with ObjectPool<T> (Microsoft.Extensions.ObjectPool) and ArrayPool<T> from the BCL. Critical for high-throughput services.

StringBuilder Pool + ArrayPool ZERO GC PRESSURE 
using Microsoft.Extensions.ObjectPool;
using System.Buffers;

// StringBuilder pool — DI registration
services.AddSingleton(ObjectPool.Create(
    new StringBuilderPooledObjectPolicy()));

// Usage in a handler
public string BuildReport(
    ObjectPool<StringBuilder> pool,
    IEnumerable<Order> orders)
{
    var sb = pool.Get();
    try
    {
        foreach (var o in orders)
            sb.AppendLine($"{o.Id}: {o.Total:C}");
        return sb.ToString();
    }
    finally { pool.Return(sb); }
}

// ArrayPool for temp buffers
var buffer = ArrayPool<byte>.Shared.Rent(4096);
try   { /* use buffer */ }
finally { ArrayPool<byte>.Shared.Return(buffer); }

06 — Concurrency

Async / Await Patterns

Async is pervasive in .NET. Common mistakes — deadlocks, fire-and-forget, sync-over-async — are preventable with consistent patterns.

🚫

Anti-Patterns to Avoid

These patterns are the most common sources of deadlocks and thread-pool starvation.

Dangerous Anti-Patterns NEVER DO 
// 1. Sync-over-async → deadlock risk
var result = GetDataAsync().Result;
var result = GetDataAsync().GetAwaiter()
                             .GetResult();

// 2. async void → exceptions uncatchable
public async void OnButtonClick() { ... }

// 3. Unobserved fire-and-forget
SendEmailAsync(user); // Task discarded!

// 4. ConfigureAwait missing in lib code
await SomeIoAsync(); // in library = bad
Correct Patterns DO THIS 
// 1. Always await
var result = await GetDataAsync();

// 2. async Task, never async void
public async Task OnButtonClickAsync() { }

// 3. Observed fire-and-forget (if needed)
_ = SendEmailAsync(user)
    .ContinueWith(t => _log.LogError(t.Exception),
        TaskContinuationOptions.OnlyOnFaulted);

// 4. ConfigureAwait in library code
await SomeIoAsync().ConfigureAwait(false);
🔀

Parallel Async — WhenAll & Channels

Run independent async operations concurrently. Use Channel<T> for producer-consumer patterns.

Task.WhenAll + CancellationToken + Channel<T> CONCURRENT 
// Run independent operations in parallel
public async Task<DashboardData> GetDashboardAsync(
    CancellationToken ct)
{
    var ordersTask  = _orderRepo.GetRecentAsync(ct);
    var statsTask   = _statsService.GetTodayAsync(ct);
    var alertsTask  = _alertService.GetActiveAsync(ct);

    await Task.WhenAll(ordersTask, statsTask, alertsTask);

    return new DashboardData(
        ordersTask.Result,
        statsTask.Result,
        alertsTask.Result);
}

// Channel<T> — producer-consumer pipeline
var channel = Channel.CreateBounded<Order>(100);

var producer = Task.Run(async () =>
{
    await foreach (var o in _feed.ReadAsync(ct))
        await channel.Writer.WriteAsync(o, ct);
    channel.Writer.Complete();
});

var consumer = Task.Run(async () =>
{
    await foreach (var o in channel.Reader.ReadAllAsync(ct))
        await _processor.ProcessAsync(o, ct);
});

await Task.WhenAll(producer, consumer);
07 — Memory

Spans & Memory

Span<T> and Memory<T> provide safe, allocation-free slicing over arrays, strings, and stack memory. Essential for parsing and high-throughput data processing.

🔪

Span<T> — Zero-Copy Slicing

Parse and process data without creating intermediate arrays or substrings.

Parsing with Span — No Heap Allocation ZERO ALLOC 
// Parse "2024-01-15" without substring allocations
public static DateOnly ParseDate(ReadOnlySpan<char> input)
{
    var dashIdx = input.IndexOf('-');
    var year    = int.Parse(input[..dashIdx]);

    var rest     = input[(dashIdx + 1)..];
    var dashIdx2 = rest.IndexOf('-');
    var month    = int.Parse(rest[..dashIdx2]);
    var day      = int.Parse(rest[(dashIdx2 + 1)..]);

    return new DateOnly(year, month, day);
}

// Called with a string — implicit conversion, no alloc
var date = ParseDate("2024-01-15");

// Stack-allocated buffer using stackalloc
Span<byte> stackBuffer = stackalloc byte[256];
int written = Encoding.UTF8.GetBytes("hello", stackBuffer);
ReadOnlySpan<byte> encoded = stackBuffer[..written];
⚠ Span<T> is a ref struct — it cannot be stored on the heap, used in async methods, or held in fields. Use Memory<T> when you need to store a slice or pass it across async boundaries.
08 — Process

Code Review Best Practices

Great code reviews are about knowledge sharing, catching bugs early, and improving design — not gatekeeping or demonstrating seniority.

👤

Author Responsibilities

Before opening a PR, the author should do these things to make the reviewer's job easier and more productive.

  • Self-review the diff before assigning reviewers — catch obvious issues yourself
  • Write a clear PR description: what changed, why, and how to test it
  • Keep PRs small and focused — ideally <400 lines changed
  • Link to the issue/ticket being addressed
  • Annotate complex sections in the PR with comments explaining non-obvious decisions
  • Ensure all CI checks pass before requesting review
  • Update or add XML doc comments for public APIs
🔎

Reviewer Guidelines — The LGTM Trap

Effective review takes focused attention. A rubber-stamp LGTM is worse than no review — it creates false confidence.

What Reviewers Should Check DO 
✓ Correctness — does the logic handle edge cases?
✓ Error handling — all exceptions handled/logged?
✓ Nullability — nullable annotations correct?
✓ Thread safety — shared state protected?
✓ Resource disposal — IDisposable wrapped in using?
✓ Naming — does intent come through clearly?
✓ Test coverage — happy + unhappy paths tested?
✓ Performance — any obvious hot-path issues?
✓ Security — user input validated/sanitised?
✓ Breaking changes — public API modifications?
Comment Tone — Be Constructive AVOID / USE 
✗ "This is wrong."
✓ "This will throw when list is empty.
   Consider using FirstOrDefault()."

✗ "Why didn't you use X?"
✓ "Have you considered using X here?
   It handles Y edge case automatically."

✗ "Nit: rename this." (with no suggestion)
✓ "Nit: processorManager → orderProcessor
   to match the domain language."

Use prefixes to set expectations:
  [blocking]  — must fix before merge
  [nit]       — minor style, non-blocking
  [question]  — genuine curiosity
  [suggestion]— take it or leave it

Real Review — Common C# Bugs to Catch

These are the patterns most likely to slip through without careful review.

IDisposable — Missing using BUG: RESOURCE LEAK 
// ✗ HttpClient created per-request — socket exhaustion
public async Task<string> FetchAsync(string url)
{
    var client = new HttpClient();  // never disposed!
    return await client.GetStringAsync(url);
}

// ✓ Inject IHttpClientFactory and let DI manage lifetime
public async Task<string> FetchAsync(
    string url, IHttpClientFactory factory)
{
    using var client = factory.CreateClient("api");
    return await client.GetStringAsync(url);
}
EF Core — N+1 Query BUG: PERFORMANCE 
// ✗ N+1: each iteration hits the database
var orders = await ctx.Orders.ToListAsync();
foreach (var o in orders)
{
    // lazy-load → separate DB round-trip per order
    var customerName = o.Customer.Name;
}

// ✓ Eager-load with Include
var orders = await ctx.Orders
    .Include(o => o.Customer)
    .AsNoTracking()          // read-only = faster
    .ToListAsync();
CancellationToken — Not Propagated BUG: UNRESPONSIVE CANCELLATION 
// ✗ CancellationToken accepted but never used
public async Task<Order> GetAsync(
    Guid id, CancellationToken ct)
{
    return await _db.Orders
        .FindAsync(id);  // ct not passed!
}

// ✓ Thread ct through every async call
public async Task<Order> GetAsync(
    Guid id, CancellationToken ct)
{
    return await _db.Orders
        .FindAsync(new object[] { id }, ct);
}
09 — Reference

PR Review Checklist

A quick-reference checklist for reviewers. Use as a mental framework — not a mechanical tick-box exercise.

🏗 Design & Architecture

  • Single responsibility — does each class/method do one thing?
  • No circular dependencies introduced
  • Public APIs are minimal and intentional
  • Domain language used in naming (ubiquitous language)
  • Interfaces not over-extracted (YAGNI)

⚡ Performance

  • No boxing of value types in hot paths
  • No unintentional closures capturing expensive objects
  • Async stream (IAsyncEnumerable) for large result sets
  • Benchmark before optimising guesses
  • No Thread.Sleep in async code — use Task.Delay

🛡 Safety & Correctness

  • Nullable reference types honoured throughout
  • Inputs validated at service boundaries
  • Exceptions caught at the right layer; not swallowed
  • CancellationToken threaded through all async calls
  • No catch (Exception) without logging & rethrowing

🧪 Testing

  • Unit tests cover the happy path
  • Edge cases covered: null, empty, boundary values
  • Tests are readable — Arrange/Act/Assert structure
  • No external calls in unit tests — dependencies mocked
  • Integration tests for EF Core / HTTP / message queues
💡 Team automation tip: Enforce standards automatically with .editorconfig, Roslyn Analyzers (Microsoft.CodeAnalysis.NetAnalyzers), and StyleCop. Reserve human review time for design, correctness, and domain logic — not formatting disputes.
